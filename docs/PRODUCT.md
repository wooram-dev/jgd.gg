# JGD.GG 제품 설계

문서 책임: 제품 목표, 대상 사용자, MVP 범위와 성공 기준을 정의한다.

## 1. 제품 한 문장

JGD.GG는 Discord 종합게임 커뮤니티 구성원이 게임 밖에서도 자주 들러 대화 소재와 서로의 기록을 발견하는 반응형 커뮤니티 라운지다. 미니게임은 함께 시간을 보내는 여러 접점 중 하나다.

## 2. 해결할 문제

Discord에서 만난 사람들이 게임이 끝난 뒤에도 자연스럽게 다시 만날 접점이 필요하다. JGD.GG는 매일 꺼낼 수 있는 대화 주제, 커뮤니티 기록과 개인 기록을 한곳에 모은다. 실제 대화는 기존 Discord 채널에서 이어가며 웹에 채팅을 복제하지 않는다.

## 3. 제품 원칙

우선순위는 다음과 같다.

1. 기록이 정확하고 기능이 안정적으로 동작한다.
2. AI 개발자가 요구사항을 임의 해석하지 않아도 된다.
3. 한 명의 운영자가 유지할 수 있다.
4. 새 게임을 추가할 수 있지만 첫 게임 때문에 범용 엔진을 만들지 않는다.
5. 클라이언트 입력을 신뢰하지 않는다.
6. 한 판 시작부터 재도전까지 마찰을 줄인다.
7. 광고보다 유용한 콘텐츠를 먼저 만든다.
8. 홈의 첫 행동은 커뮤니티 콘텐츠 탐색이며 게임 시작을 강요하지 않는다.
9. 실제 데이터가 없는 온라인 인원, 게시글, 참여자, 일정과 알림을 꾸며 표시하지 않는다.
10. 포인트는 참여를 보조하는 수단이며 게임 점수·랭킹의 정확성이나 공정성을 바꾸지 않는다.

## 4. 사용자

### 4.1 주 사용자

- 운영 중인 한국어 Discord 종합게임 서버의 구성원
- 주로 PC를 사용하지만 모바일에서도 플레이하는 사용자
- 게임 전후에 친구들의 활동을 둘러보고, 대화할 거리를 찾거나 가볍게 기록에 도전하려는 사용자

### 4.2 보조 사용자

- Discord 계정은 있지만 대상 서버 구성원이 아닌 방문자
- 로그인하지 않고 게임과 랭킹을 둘러보는 방문자
- 서비스 운영자

### 4.3 MVP 접근 정책

MVP는 Discord 계정이면 누구나 공식 플레이할 수 있게 한다.

이유:

- 공식 플레이에는 대상 서버 멤버 판정을 요구하지 않는다.
- 공유된 랭킹 링크에서 방문자가 바로 체험할 수 있다.
- 외부 사용자가 생겨도 핵심 데이터 모델을 바꿀 필요가 없다.
- 커뮤니티 전용성이 실제로 필요해진 뒤 회원 게이트를 추가할 수 있다.

게임 프로필은 대상 Discord 서버 멤버 전용이다. 이 권한은 프로필 등록·열람에 적용하며 기존 홈·연습·공식 플레이·랭킹의 접근 정책은 유지한다. 상세는 AUTH.md를 따른다.

## 5. 핵심 사용자 흐름

### 5.1 비로그인 방문자

홈에서는 오늘의 대화 주제 → 공개 커뮤니티 기록 → 선택적인 미니게임 순으로 탐색한다. 대화 주제는 종류를 골라 복사하고 평소 이용하는 Discord 채널에 직접 붙여넣는다. 서버 초대나 메시지 자동 전송으로 오인시키지 않는다.

게임을 선택한 뒤의 흐름:

1. 홈 또는 number-click 페이지에 접속한다.
2. 규칙, 오늘 최고 기록, 공개 랭킹을 본다.
3. 로그인 없이 연습 플레이를 시작한다.
4. 완료 결과에 연습 기록임을 명확히 본다.
5. 공식 기록 등록 안내를 보고 Discord 로그인할 수 있다.
6. 로그인하더라도 방금 연습 기록은 등록되지 않으며 새 공식 플레이가 필요하다.

### 5.2 로그인 사용자

1. Discord로 로그인한다.
2. number-click 페이지에서 개인 최고와 오늘 최고를 본다.
3. 시작 버튼을 눌러 서버 세션과 보드를 받는다.
4. 1부터 25까지 순서대로 누른다.
5. 서버가 제출을 검증하고 최종 기록을 반환한다.
6. 결과 화면에서 개인 최고 여부와 현재 기간 순위를 본다.
7. 페이지 이동 없이 다시 플레이한다.

### 5.3 랭킹 방문자

1. 오늘, 이번 주, 전체 탭 중 하나를 고른다.
2. 기간별 사용자 최고 기록만 정렬된 목록을 본다.
3. 로그인 상태면 자신의 행 또는 별도 내 순위 카드가 강조된다.

## 6. MVP 범위

### 6.1 포함

- 커뮤니티 라운지 홈과 공통 탐색 레이아웃
- 홈 배너를 대체하는 로그인 멤버 사진 스토리: [features/stories.md](features/stories.md)의 게시·만료·원본 보관 정책
- 오늘의 대화 주제: 가벼운 수다·게임 이야기 두 종류, KST 날짜별 14개 주제 순환, 클립보드 복사와 실패 시 직접 복사
- 실제 오늘 TOP 5, 주간 랭킹 진입, 내 기록 진입과 라운지 이용 가이드
- Discord OAuth 로그인·로그아웃
- 사용자 생성과 로그인 시 프로필 갱신
- 멤버 전용 수동 게임 프로필: `/내정보` 등록·수정·삭제와 `/멤버`의 게임별 열람 ([features/game-profiles.md](features/game-profiles.md))
- 비로그인 연습 플레이
- 로그인 공식 number-click 플레이
- 서버 발급 GameSession
- 실제 시간, 오클릭, 페널티, 최종 기록 저장
- 개인 최고 기록과 플레이 횟수
- 오늘, 이번 주, 전체 랭킹
- 공식 number-click 완료당 10P와 KST 일일 50P 한도의 사용자별 포인트 적립
- 확정 포인트 잔액, 최근 적립·회수 내역과 기록 무효화 회수
- 중복 완료 방지와 기본 부정 기록 검증
- PC·모바일 반응형 UI
- 로딩, 빈 상태, 인증 실패, 네트워크 실패 UX
- unit, API/integration, 핵심 E2E 테스트
- 개인정보 최소 수집과 계정 차단 기반

### 6.2 명시적 비범위

- 같이 게임할 사람 모집
- 실시간 채팅, 음성, 친구, 쪽지
- 실시간 멀티플레이와 게임 서버 제어
- 포인트 사용·상점·아이템·경험치·레벨
- 시즌, 업적, 푸시 알림
- 광고 노출·관리·수익 최적화
- 복잡한 관리자 페이지
- 고급 치트 탐지, 리플레이, Steam 연동
- 다중 Discord 서버 SaaS 관리
- Redis, event bus, CQRS, microservice, Kubernetes

비범위 항목은 관련 데이터 테이블이나 빈 메뉴를 미리 만들지 않는다.

## 7. MVP 화면

| 경로 | 공개 여부 | 목적 |
|---|---|---|
| / | 공개 (스토리 프로필 목록 공개, 사진 열람·게시는 로그인 필요) | 멤버 사진 스토리, 오늘의 대화, 커뮤니티 기록, 개인 영역 진입, 보조 미니게임 |
| /games/number-click | 공개 | 연습 또는 공식 플레이와 결과 |
| /rankings/number-click | 공개 | 오늘·주간·전체 랭킹 |
| /내정보 | 로그인 필요 (게임 프로필은 대상 서버 멤버 필요) | 내 게임 프로필 편집, 포인트와 공식 기록 요약 |
| /멤버 | 로그인·대상 서버 멤버 필요 | 멤버별 게임 프로필과 게임 필터 |
| /login | 공개 | Discord 로그인과 개인정보 안내 |
| /auth/error | 공개 | 인증 실패 이유와 재시도 |

게임 프로필은 `/내정보`에서 편집한다. Discord 이름과 아바타는 Discord 값을 따른다.

기존 `/me`, `/members` 페이지 주소는 각각 `/내정보`, `/멤버`로 308 이동한다. query와 fragment는 유지하며 API 경로는 변경하지 않는다.

## 8. 성공 기준

### 8.1 기능 성공

- 정상 로그인 사용자가 한 번의 페이지 흐름 안에서 플레이, 저장, 랭킹 반영, 재도전을 완료한다.
- 같은 세션을 여러 번 제출해도 GameRecord는 정확히 한 건이다.
- 같은 공식 기록을 여러 번 제출해도 포인트는 한 번만 적립되고 KST 일일 한도를 넘지 않는다.
- 기간별 랭킹은 사용자당 한 건만 표시한다.
- 모바일 320px 너비와 지원 데스크톱 브라우저에서 보드가 잘리거나 겹치지 않는다.
- 핵심 품질 게이트가 모두 통과한다.

### 8.2 출시 후 관찰 지표

추적 도구를 MVP 필수 dependency로 만들지는 않는다. DB 집계 또는 배포 플랫폼 기본 분석으로 아래를 확인한다.

- 일간 공식 플레이 사용자 수
- 사용자당 일간 공식 완료 횟수
- 7일 내 재방문 사용자 비율
- 라운지 재방문과 대화 주제 이용, 라운지에서 기록 탐색으로 이어지는 비율 (현재 별도 추적 코드 없음)
- 시작 세션 대비 유효 완료율
- 연습 완료 후 로그인 전환 수
- API 오류율과 완료 제출 거절 사유

초기 제품 가설 검증 목표값은 출시 후 4주 데이터를 보고 정한다. 데이터가 없는 상태에서 임의 KPI 숫자를 성공 조건으로 고정하지 않는다.

## 9. 수익화 원칙

- MVP에 광고 SDK나 광고 슬롯을 넣지 않는다.
- 향후 데스크톱 넓은 화면에 콘텐츠 외부 보조 열을 추가할 수 있도록 중앙 콘텐츠 너비를 제한한다.
- 게임 보드, 결과, 시작·재도전 버튼 사이에는 광고를 삽입하지 않는다.
- 모바일에서 게임 시작 전후 전체 화면 광고를 사용하지 않는다.
- 광고 도입은 실제 반복 사용과 콘텐츠 품질을 확인한 뒤 별도 요구사항으로 승인한다.

## 10. 이후 확장 순서

사용자별 포인트 적립 v1은 승인돼 활성화됐다. 로그인 사용자마다 독립된 포인트 잔액을 제공하되 게임 점수와 분리하고, 서버가 확인한 공식 number-click 완료만 [features/points.md](features/points.md)의 정책에 따라 중복 없이 반영한다.

그 밖의 MVP 이후 우선순위 후보:

1. 라운지 재방문과 대화 주제 이용 피드백을 바탕으로 콘텐츠 개선
2. 포인트 사용처·상점 요구사항 검토
3. 실제 커뮤니티 요구에 따른 서버 투표·이벤트 설계
4. 운영 지표에 따른 number-click 개선과 두 번째 게임 검토
5. 통계와 개인 기록 추이
6. 업적·시즌
7. 필요가 입증된 경우 대상 Discord 서버 멤버 게이트
8. 사용량이 충분한 경우 비침해적 광고

포인트 사용과 상점 등 후속 기능은 담당 Source of Truth, 코드와 테스트가 함께 준비된 뒤 별도로 활성화한다.

## 11. 제품 Acceptance Criteria

- [ ] 홈에서 게임을 시작하지 않아도 대화 주제와 커뮤니티 기록을 탐색한다.
- [ ] 대화 주제는 KST 날짜별로 일관되며 종류 선택·복사·복사 실패 복구가 가능하다.
- [ ] 연결 불가, 조회 오류와 실제 빈 기록을 구분하며 가상의 활동을 표시하지 않는다.
- [ ] 공개 방문자는 로그인 없이 홈, 게임 설명, 연습 플레이, 모든 랭킹을 이용한다.
- [ ] 비로그인 완료 결과에는 공식 저장이 아니며 소급 등록되지 않는다는 문구가 보인다.
- [ ] 로그인 사용자는 Discord 프로필로 식별되고 공식 기록을 저장한다.
- [ ] number-click 규칙과 점수 산식이 모든 화면·API·DB에서 동일하다.
- [ ] 오늘·이번 주·전체 랭킹과 개인 최고를 확인할 수 있다.
- [ ] 로그인 사용자는 포인트 잔액과 최근 변동을 확인하며 공식 기록당 적립과 일일 한도가 정확하다.
- [ ] 명시적 비범위 기능의 코드, 메뉴, 테이블이 생성되지 않는다.
- [ ] PC와 모바일에서 핵심 흐름이 E2E 테스트를 통과한다.
- [ ] TESTING.md의 출시 게이트가 모두 통과한다.
