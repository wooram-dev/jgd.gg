# 멤버 게임 프로필 v1

문서 책임: 사용자가 작성하는 게임 프로필의 동작과 수락 기준.

## 범위와 흐름

대상 Discord 서버 멤버가 `/내정보#game-profile`에서 LoL, PUBG, Overwatch를 선택해 닉네임과 선택 입력 티어를 작성한다. 게임마다 한 항목을 허용한다. 티어는 자유 텍스트이며 `지원 다이아몬드 3`처럼 역할·모드를 함께 적을 수 있다.

저장 성공 후 서버가 반환한 카드를 표시한다. 카드에는 `사용자 입력`과 계정 소유·공식 티어 미확인 안내가 있다. 편집 취소는 저장된 값으로 돌아가며 게임 선택 해제 후 저장하면 해당 항목이 삭제된다. 마지막 게임까지 지우려면 `프로필 삭제 → 삭제 확인`으로 전체 카드를 삭제한다.

`/멤버`는 멤버별 카드, 게임별 필터와 페이지 이동을 제공한다. 동일한 Discord 표시 이름도 별도 카드로 유지한다. 게임 데이터의 원본은 JGD.GG DB다. 기존 bot과 자동 동기화하지 않는다. 게임 계정 인증, 외부 전적 조회, Steam 연결, 티어 평가, `/게임궁합`과 bot 명령 변경은 이 버전의 비범위다.

## 공개·보존·오류

- 조회자와 작성자의 접근 자격은 [AUTH.md](../AUTH.md)의 게임 프로필 전용 정책을 따른다. Discord 이름·아바타는 기존 로그인 동기화 값을 사용한다.
- 등록 정보는 직접 수정·삭제하거나 계정을 삭제할 때까지 보관한다. 서버 탈퇴 시 노출과 접근을 중단하되 자동 삭제하지 않는다. 탈퇴·차단 후 삭제는 `contact@jgd.gg`로 요청한다. 변경 이력은 별도 축적하지 않는다.
- 저장 전 서버 멤버 공개·사용자 입력·보관과 삭제 안내를 표시한다.
- 미등록, 로딩, 접근 불가, 일시적 확인 실패, 조회 실패를 구분한다.
- 일반 저장 실패는 입력을 유지하고 재시도한다. 인증·멤버 확인 실패는 기존 카드와 편집 필드를 숨긴 뒤 다시 확인하기를 제공한다.
- 중복 제출은 처리 중 잠근다. 저장·삭제 완료는 live region과 섹션 제목 focus로 알린다.
- 동시 요청은 카드 전체 단위로 직렬 처리하고, 나중 요청이 앞선 저장을 대체한다. 서로 다른 요청의 게임 항목이 섞이지 않는다.

## Acceptance Criteria

- GP-1: 세 게임을 등록·수정하고 선택 해제·전체 삭제를 DB에 반영한다.
- GP-2: 닉네임 필수·티어 선택, 길이·중복·지원 게임·추가 필드 제한을 검증한다.
- GP-3: 모든 카드에 사용자 입력·미인증 안내를 표시하고 Discord identity는 변경하지 않는다.
- GP-4: 비로그인·만료·차단·비멤버·멤버 확인 장애를 서버에서 차단한다. canonical Discord ID만 사용한다.
- GP-5: DTO는 내부 userId·Discord ID·token을 제외하며 no-store다. 타인 수정·삭제 입력을 받지 않는다.
- GP-6: 게임 필터·페이지 이동을 지원하고 탈퇴·차단 작성자를 숨긴다.
- GP-7: 동시 저장·실패 rollback·DB 제약·계정 삭제 cascade를 검증한다.
- GP-8: 실패 후 입력 유지·재시도, 중복 제출 방지, 삭제 확인, 키보드·320px 이상 레이아웃을 검증한다.

## 설정과 적용

1. 기존 bot 서버의 ID를 `TARGET_GUILD_ID`, bot token을 `DISCORD_BOT_TOKEN` 서버 환경 변수로 설정한다. bot 저장소의 `GUILD_ID`, `DISCORD_TOKEN`에 대응한다. 값은 클라이언트·Git·로그에 넣지 않는다.
2. 대상 DB와 데이터 보존·승인 범위를 확인하고 `pnpm db:deploy`로 additive migration을 적용한다. 테스트는 전용 `_test` DB만 사용한다.
3. 앱을 빌드·재시작하고 실제 멤버·비멤버로 접근을 확인한다.

설정이 없으면 게임 프로필 요청은 503으로 차단되고 기존 공개 기능은 유지된다. bot 프로세스 재시작·명령 동기화는 필요하지 않다. 되돌릴 때는 앱 버전을 되돌리고 새 테이블은 보존한다.
