# 포인트 기능 설계 지침

문서 책임: 사용자별 포인트의 목적, 소유권, 적립·사용 정책, 정합성, 보안, UX와 Acceptance Criteria를 정의한다. 실제 테이블·제약은 DATABASE.md, HTTP 계약은 API.md가 담당한다.

## 1. 상태와 범위

사용자별 포인트 적립 v1은 활성 기능이다. 공식 number-click 완료 적립, 본인 잔액·최근 원장 조회와 기록 무효화 회수만 포함한다. 포인트 사용·상점·사용자 간 이전·운영자 조정 UI는 별도 제품 요구사항이 승인되기 전까지 비범위다.

DATABASE.md, API.md, AUTH.md, UI_GUIDE.md와 TESTING.md의 활성 계약을 함께 따른다. 빈 상점 메뉴나 임시 잔액은 노출하지 않는다.

## 2. 목적

- 로그인 사용자의 지속적인 커뮤니티 참여를 보조한다.
- 포인트는 서비스 안의 참여 지표이며 number-click의 기록 점수나 랭킹과 별개다.
- 포인트 보유량으로 게임 결과, 개인 최고 또는 공개 랭킹 순서를 바꾸지 않는다.
- 현금, 가상자산 또는 환불 가능한 결제 수단으로 표현하지 않는다.

## 3. 사용자와 소유권

- 서비스에 가입된 사용자마다 내부 `user.id`에 연결된 포인트 계정 하나를 가진다.
- 최초 활성화 시 잔액은 0이다.
- Discord 표시 이름이나 avatar가 바뀌거나 재로그인해도 같은 user이면 잔액과 원장은 유지된다.
- 비로그인 연습 플레이에는 영구 포인트 계정을 만들지 않고, 로그인 후 과거 연습 기록을 소급 적립하지 않는다.
- BANNED 사용자는 자신의 확정 잔액과 내역을 조회할 수 있지만 새 적립과 사용은 할 수 없다.
- 기록 무효화에 따른 회수와 감사용 정정은 사용자 상태와 관계없이 서버만 처리할 수 있다.
- 계정 삭제가 처리되면 포인트 데이터도 AUTH.md와 DATABASE.md의 사용자 삭제 정책을 따른다.

## 4. 단위와 잔액 원칙

- 포인트는 소수점 없는 0 이상의 정수이며 UI 단위는 `P`다.
- 잔액은 적립 합계에서 사용·회수 합계를 뺀 확정값이다.
- 초기 버전은 사용자 간 이전, 현금 구매·환전, 만료, 마이너스 잔액을 지원하지 않는다.
- 게임의 `ScoreUnit.POINTS`와 사용자 보상 포인트는 이름이 비슷해도 다른 개념이다. API field와 DB model에서 서로 구분되는 이름을 사용한다.

## 5. 적립 정책

포인트는 서버가 유효성을 확인하고 영구 저장한 활동에만 적립한다. 클라이언트가 사용자 ID, 적립량, 잔액 또는 적립 완료 여부를 결정할 수 없다.

적립 정책 v1은 다음 값으로 고정한다.

| 항목 | 값 |
|---|---|
| 정책 버전 | `number-click-completion-v1` |
| 적용 시작 | 2026-09-12 01:12:00 Asia/Seoul (`2026-09-11T16:12:00.000Z`) |
| 적립 활동 | 적용 시작 이후 서버가 유효하게 저장한 number-click 공식 GameRecord |
| 기록당 적립량 | 10P |
| 사용자별 한도 | KST 하루 50P, 즉 최대 5개 기록 |
| 반복 범위 | 서로 다른 유효 GameRecord는 한도 안에서 반복 적립 허용 |

하루 여섯 번째 이후 기록에는 부분 적립이나 다음 날 소급 적립을 하지 않는다. 다음 KST 날짜의 첫 유효 기록부터 다시 적립한다. 적용 시작 이전 기록, 연습 플레이, 거절·만료·포기 session과 처음부터 무효인 기록에는 적립하지 않는다.

같은 원인 활동은 재시도, 동시 요청 또는 완료 API replay와 관계없이 정확히 한 번만 적립한다. 이미 보상한 GameRecord가 나중에 무효화되면 기존 적립 내역을 수정·삭제하지 않고 같은 양의 회수 내역을 추가한다.

## 6. 사용 정책

포인트 사용은 v1에 포함하지 않고 별도 제품 요구사항이 승인된 뒤 추가한다. 사용 기능을 도입할 때는 다음을 지킨다.

- 서버가 허용한 상품이나 행동만 고정된 정책 가격으로 처리한다.
- 잔액보다 큰 사용 요청은 전체를 거부하며 부분 차감하지 않는다.
- 차감과 대상 효과 적용은 하나의 원자적 처리로 성공하거나 함께 실패한다.
- 재시도와 동시 요청에도 같은 사용 요청은 정확히 한 번만 반영한다.
- 사용자 간 선물·이전과 운영자 임의 수정 UI는 별도 보안·감사 설계 없이는 추가하지 않는다.

## 7. 원장과 정합성

구현은 사용자별 현재 잔액과 append-only 변동 원장을 함께 관리한다. 정확한 model과 column은 DATABASE.md에 정의한다.

각 변동은 최소한 다음 의미를 추적할 수 있어야 한다.

- 적립, 사용, 회수 또는 승인된 운영 조정 구분
- 정수 증감량과 처리 후 잔액
- 원인 활동 또는 사용 요청의 안정된 식별자
- 적용한 정책 버전
- 멱등성 식별자와 서버 처리 시각

잔액 변경과 원장 추가는 같은 DB transaction에서 처리한다. 사용자 포인트 계정을 잠근 뒤 새 잔액이 0 이상인지 확인하고, 원인 활동 또는 멱등성 식별자의 unique 제약으로 중복을 최종 방어한다.

과거 원장 row의 증감량, 원인과 처리 후 잔액은 수정하지 않는다. 정정은 반대 방향의 새 변동으로 남긴다. 현재 잔액과 원장 합계가 다르면 새 적립·사용을 중단하고 운영자가 복구할 수 있도록 오류와 감사 정보를 남긴다.

## 8. API와 권한 원칙

- 잔액과 변동 내역은 로그인한 본인만 조회한다. 공개 포인트 랭킹은 별도 승인 없이는 만들지 않는다.
- mutation은 인증, DB의 ACTIVE 상태, same-origin Origin, strict schema와 멱등성을 검증한다.
- 임의 증감량을 받는 범용 사용자 API를 만들지 않는다. 서버가 활동 또는 상품 정책에서 증감량을 계산한다.
- 타인의 포인트 계정 존재 여부를 추측할 수 없게 소유권 오류를 처리한다.
- 성공 응답은 transaction에서 확정된 잔액을 반환한다. 실패를 성공처럼 표시하거나 클라이언트 계산으로 보정하지 않는다.

정확한 endpoint, request·response schema와 오류 code는 API.md를 따른다.

## 9. UI 원칙

로그인 사용자는 공통 header와 `/내정보`에서 현재 확정 잔액을 확인한다. `/내정보`에는 최근 변동의 사유, 증감량과 시각을 제공한다.

- 포인트와 게임 기록을 시각적·문구상 명확히 구분한다.
- 적립·사용 중 예상 잔액을 확정값처럼 표시하지 않는다.
- loading, 빈 내역, 조회 실패와 처리 실패를 구분한다.
- 증감 방향을 부호와 텍스트로 제공해 색에만 의존하지 않는다.
- 잔액과 변동 숫자에는 tabular-nums와 locale 구분자를 사용한다.

상세 배치와 접근성은 UI_GUIDE.md를 따른다.

## 10. 운영과 악용 방지

- 적립량과 한도 변경은 정책 버전을 올리고 적용 시작 시각을 기록한다. 과거 원장을 새 정책으로 다시 계산하지 않는다.
- 포인트 변동 log에 Discord ID, token, cookie 또는 전체 요청 payload를 남기지 않는다.
- 지급량, 중복 차단 건수, 회수, 잔액 불일치와 mutation 오류율을 관찰한다.
- 비정상 반복 적립이 발견되면 해당 적립 source를 중단할 수 있어야 하며 과거 원장을 삭제하지 않는다.
- 운영 조정이 필요하면 사유, 담당자, 증감량과 시각을 감사 가능하게 남기며 사용자 입력으로 실행할 수 없다.

## 11. 테스트 기준

구현 시 최소한 다음을 검증한다.

- 신규 사용자 0P 생성과 기존 사용자 재로그인 시 잔액 유지
- 비로그인·BANNED 사용자의 mutation 거부
- 유효한 활동 한 건의 정확한 적립
- 같은 활동의 순차·동시 replay가 한 번만 적립됨
- 적립 한도와 정책 버전 경계
- 사용 기능이 승인될 때 잔액 부족 시 차감과 대상 효과가 모두 반영되지 않음
- 사용 기능이 승인될 때 성공한 사용의 차감과 대상 효과가 원자적으로 반영됨
- 기록 무효화 시 원본 보존과 회수 내역 추가
- 타인 잔액·내역 접근 차단
- 잔액과 원장 합계 정합성, 음수와 정수 범위 DB 제약
- 모바일, keyboard, screen reader 상태 문구와 네트워크 실패 복구

## 12. Points Acceptance Criteria

- [ ] 서비스에 가입된 사용자마다 독립된 포인트 계정과 0 이상의 정수 잔액이 하나 있다.
- [ ] 포인트는 게임 점수·랭킹과 분리되며 결과 공정성에 영향을 주지 않는다.
- [ ] 서버가 확인한 활동만 정책 버전과 한도에 따라 적립한다.
- [ ] 같은 원인 활동은 재시도·동시 실행에도 정확히 한 번만 반영되고, 향후 사용 요청에도 같은 원칙이 적용된다.
- [ ] 잔액과 append-only 원장이 같은 transaction에서 갱신되고 과거 내역을 덮어쓰지 않는다.
- [ ] 음수 잔액, 비로그인, BANNED 적립과 타인 소유 요청이 안전하게 거부된다.
- [ ] 연습 플레이는 소급 적립되지 않고 무효화된 공식 기록은 회수 내역으로 상쇄된다.
- [ ] 본인은 확정 잔액과 변동 사유를 확인하며 loading·빈 상태·오류를 구분한다.
- [ ] 확정된 v1 적립만 활성화하며 사용처가 확정되기 전에는 차감이나 빈 상점 UI를 활성화하지 않는다.
- [ ] 관련 DB, API, Auth, UI와 테스트 Source of Truth가 같은 구현 변경에서 동기화된다.
