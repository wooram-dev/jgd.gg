# 포인트 칭호 상점 v1

문서 책임: 칭호 구매·소장·장착·Discord 역할 적용과 실패 복구 정책. DB·HTTP·인증 계약은 각 담당 문서를 따른다.

## 상품과 구매

| 상품 키 | 게임 | 칭호 | 가격 |
|---|---|---|---:|
| lockdown | 락다운 프로토콜 | 피자스시 장인 | 500P |
| overwatch | 오버워치 | 탱장연 | 500P |
| lol | 롤 | 서폿은 도구다 | 500P |
| pubg | 배그 | 보급은 못참지 | 500P |
| minecraft | 마인크래프트 | 침대 좀 누워 | 500P |
| valorant | 발로란트 | 뭔헤드야 | 500P |

- 여러 칭호를 영구 소장하고 하나만 장착한다. 같은 칭호는 중복 구매할 수 없다.
- 잔액이 부족하면 구매 전체를 거부한다. 확정된 구매는 환불하지 않는다.
- 구매하면 해당 칭호의 장착을 요청한다. 기존 칭호 소장은 유지한다.
- 소장 칭호 간 교체와 장착 해제는 무료다. 해제하면 장착 칭호가 없으며 소장권은 유지한다.
- 로그인한 본인만 소장 목록을 조회한다. 구매·장착·재적용은 ACTIVE 대상 Discord 서버 멤버만 가능하다. BANNED 사용자는 소장 조회만 가능하다.
- 상품은 코드에 정의한 여섯 개뿐이다. 임의 가격·상품·역할 ID·사용자 ID를 입력받지 않는다.
- 선물·이전·사용자 환불·역할 생성·관리자 상점 UI는 제공하지 않는다.

## 화면

`/상점`은 로그인 후 게임별 상품 카드·가격·확정 잔액·소장 여부·장착 상태를 보여준다. 공통 메뉴와 `/내정보#titles`의 내 칭호에서 진입한다. 기존 `/shop`은 query를 보존해 `/상점`으로 308 이동한다.

구매 전 dialog에 상품명·500P·구매 후 예상 잔액·영구 소장·자동 장착·환불 불가를 표시한다. 취소와 Escape는 원래 구매 버튼으로 focus를 복구한다. 처리 중 중복 제출을 막고, 성공 후 제목 focus·상태 문구와 확정 잔액을 갱신한다. 공통 header와 같은 화면의 포인트 내역도 갱신한다.

`/내정보#titles`는 소장한 칭호만 표시하며 교체·해제·Discord에 다시 적용을 제공한다. 적용 대기 중에는 새 구매·교체를 막고 현재 요청의 재시도를 제공한다. 오류와 로딩, 빈 소장 목록, 판매 준비 중, 조회 전용 계정을 구분한다.

## 구매와 원장

차감·사용 원장·소장권·장착 요청을 같은 DB transaction에서 확정한다. 사용자별 장착 상태와 포인트 계정을 잠그고 잔액·원장 합계를 확인하며, 하나라도 실패하면 모두 rollback한다. Discord HTTP 요청은 구매 transaction 밖에서 실행한다.

구매 요청 UUID는 사용자별로 고유하다. 같은 요청·같은 상품은 기존 구매를 반환하며 다시 차감하거나 다시 장착 요청을 만들지 않는다. 같은 키를 다른 상품에 쓰면 충돌이다. 다른 키로 같은 상품을 동시에 구매해도 소장 unique 제약으로 중복 차감을 막는다. 응답 유실 재시도는 원래 키를 사용한다.

기존 포인트의 적립 정책은 변경하지 않는다. 부정 탐지·사후 제재 확장은 별도 작업이다. 기존 서버 내부 `invalidateGameRecord`는 그대로 전액 회수 또는 전체 rollback하며, 사용 후 잔액 부족 시 자동 환불·칭호 회수·부채·향후 적립 상계를 도입하지 않는다. 잔액 부족 시 운영자가 해당 예외를 확인해야 하며 이 함수를 자동 부정 탐지로 설명하지 않는다.

## 장착과 외부 적용

DB에 원하는 칭호, 마지막 적용 확인 칭호, revision, 적용 대기 여부와 재시도 가능 시각을 저장한다. 장착 입력의 `expectedRevision`으로 오래된 탭·재전송이 이후 선택을 덮어쓰지 못하게 한다. 직전 동일 요청의 재전송만 허용한다.

역할 적용은 사용자별 DB row lock으로 직렬화한다. 다른 적용이 진행 중이면 중복 외부 호출을 시작하지 않는다. 기존 상점 칭호 역할을 제거한 뒤 새 역할을 추가하고, 멤버 역할을 다시 읽어 실제로 하나 또는 없음인지 확인해야 완료다. 상점 외 역할은 수정하지 않으며, 멤버 전체 역할 목록을 PATCH로 덮어쓰지 않는다.

timeout·일부 적용·429·권한 변경·탈퇴·DB 응답 유실에는 대기 상태를 보존한다. 재시도는 현재 Discord 상태를 읽어 같은 목표로 맞추며 추가 차감하지 않는다. 429는 Discord 대기 시간을 따르고 다른 장애는 기본 30초 후 재시도한다. 구매가 확정됐으면 지급 장애를 이유로 환불하지 않고 역할 연결·권한을 복구한다.

프로세스 재시작·브라우저 종료 후에도 요청은 DB에 남는다. 상점이나 내 칭호에서 `Discord에 다시 적용`으로 복구한다. 페이지를 닫아도 계속 실행되는 자동 worker는 없다. Discord와 DB의 순간적인 일치, 또는 timeout 뒤 늦게 처리되는 외부 요청까지 원자적으로 취소되는 것을 보장하지 않는다. 실제 역할이 바뀌었거나 재가입한 경우에도 같은 버튼으로 복원한다.

## 역할 설정

서버 환경 변수:

- `DISCORD_BOT_TOKEN`: 기존 봇 token.
- `TARGET_GUILD_ID`: 단일 대상 서버.
- `DISCORD_TITLE_ROLE_IDS`: 위 여섯 상품 키를 서로 다른 Discord 역할 ID에 연결한 JSON object. 여섯 키가 모두 있어야 한다. 실제 값은 Git·브라우저·로그에 넣지 않는다.

token·서버·역할 연결이 누락되거나 형식이 잘못되면 판매 준비 중으로 표시하고 구매를 차단한다. 구매 전과 적용 전에 실제 Discord 멤버, 봇 권한·역할 계층, 상품 역할과 채널 권한을 읽어 확인한다. 상품 역할은 봇 최상위 역할 아래의 unmanaged 역할이어야 하고, 서버 권한은 0이며 채널별 권한 허용도 없어야 한다. 역할은 상점 전용으로 만들고 다른 봇·자동 역할·일반 서버 권한에 재사용하지 않는다.

한 사용자의 첫 요청에 서버·역할 연결의 해시를 저장한다. 연결이 나중에 달라지면 구매·교체·적용을 차단해 이전 칭호 역할을 남긴 채 새 역할을 지급하지 않는다. 역할 교체가 필요하면 운영자가 기존 역할을 정리하고 DB 상태·연결을 함께 이관해야 한다. 설정을 단순 변경해 자동 복구된다고 안내하지 않는다.

서버 탈퇴·차단에도 소장은 보존한다. 자동 탈퇴·차단 이벤트 처리와 Discord 역할 회수는 이 버전에 없으며 운영자는 필요 시 Discord에서 처리한다. 사용자 계정 삭제 전에도 역할을 먼저 확인·제거하고, 사용자 삭제는 구매·장착·원장을 cascade 삭제한다.

봇 프로세스의 새 명령이나 재시작은 필요하지 않다. 웹 서버가 봇 identity로 REST를 호출한다. 공식 계약은 [멤버 역할 추가·제거](https://docs.discord.com/developers/resources/guild#add-guild-member-role), [역할 계층·권한](https://docs.discord.com/developers/topics/permissions#permission-hierarchy)을 따른다.

## 적용과 복구

1. 실제 Discord에 장식용 전용 역할 여섯 개를 준비하고 서버 환경을 설정한다.
2. 대상 DB·backup을 확인한 배포 단계에서 enum 확장과 상점 테이블 migration 두 개를 순서대로 적용한다. 기존 사용자·기록·포인트는 변경하지 않는다.
3. 앱을 빌드·배포하고 실제 멤버의 구매·교체·해제와 비멤버 차단을 확인한다. 자동 테스트는 실제 Discord 역할을 변경하지 않는다.
4. 문제 발생 시 신규 판매를 중단하고 소장·대기·원장을 보존한다. SPEND 원장 도입 이후 구버전 UI는 해당 enum을 지원하지 않으므로 구매 전 버전으로 단순 rollback하지 않는다. 데이터 보존 상태에서 forward-fix한다.

## Acceptance Criteria

- TS-1: 여섯 칭호 500P, 잔액 부족·중복 구매 차단, 여러 개 소장·하나만 장착·무료 해제.
- TS-2: 차감·소장·원장·장착 요청의 원자성, 요청 유실·동시 구매·재전송의 중복 차감 방지.
- TS-3: 본인 조회, ACTIVE 멤버 mutation, Origin·strict schema·body 크기·설정 실패 차단과 식별자 비노출.
- TS-4: 소유권·가격·원장 형태·음수 잔액·unique·cascade DB 제약.
- TS-5: 상점 외 역할 보존, 제거 후 추가·실제 확인, 안전한 역할과 봇 권한 검증.
- TS-6: 역할 적용 직렬화, 대기 지속성·대기 시간·무료 재시도, 오래된 revision 거부.
- TS-7: 구매 확인·취소 focus·처리 중 상태·잔액과 원장 갱신·오류 복구, desktop/mobile/320px.
- TS-8: 테스트 전용 Discord 대체는 기존 test/mock-discord 이중 조건과 고정 OAuth fixture에만 허용.
